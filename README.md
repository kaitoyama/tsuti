# tsuti

通知・事務連絡の**新旧対照表**をプレーンテキストで扱うためのツールです。改正を旧版に機械的に反映し、同じデータから新旧対照表（HTML）を自動で作ります。番号の繰下げに合わせて「２⑪を準用」のような参照も自動で書き直します。

## すぐ試す（データ不要）

```bash
pip install -r requirements.txt
cd examples
python ../shinkyu.py apply sample.tsuchi.txt sample_改正.shinkyu.txt -o sample_v2.tsuchi.txt --patch-out sample_改正_完成版.shinkyu.txt
#   参照を追従: /第１/２/③  １② → １③
#   参照を追従: /第１/３/①  １② → １③
python ../shinkyu.py render sample_改正_完成版.shinkyu.txt -o sample_新旧対照表.html
```

`examples/` の文書は、形式を説明するための架空の例です。

---

以下、形式の説明です。


通知の**全文**と**改正**を、どちらもプレーンテキストで管理するための形式です。改正は旧版に機械的に反映でき、同じファイルからそのまま新旧対照表を作れます。
Lawtext（法令のプレーンテキスト形式）の考え方をもとに、通知向けに作っています。

```
 通知テキスト（R7）  ──apply(改正)──▶  通知テキスト（R8）
        │                                   │
        └──────────── diff ─────────────────┘
                        ▼
              新旧対照表テキスト（改正そのもの）──render──▶ 新旧対照表（HTML）
                        ▲
     既存の新旧対照表PDF ──pdf2shinkyu（初回取り込み）
```

## 1. 通知テキスト（`*.tsuchi.txt`）＝ ある版の全文

```text
---
title: 介護給付費算定に係る体制等に関する届出等における留意点について
version: R6.3.15
history:
- {kind: 制定, number: 老発0315第1号, date: '2024-03-15'}
---
前文
  　「指定居宅サービスに要する費用の額の算定に関する基準」（平成12年…期されたい。
  　なお、「指定居宅サービス…廃止する。
第５　体制状況一覧表の記載要領について
  ２　訪問介護
    ⑪　「介護職員等処遇改善加算」については、大臣基準告示第四号イに該当する場合に…
    ⑧　「中山間地域等における小規模事業所加算」における…
      　また、「規模に関する状況」については、…          ← 字下げした2段落目
```

| 規則 | 内容 | Lawtextとの関係 |
|---|---|---|
| 1行＝1項目 | 「ラベル＋全角空白＋本文」の形。PDFの折り返しは行に戻す | 同じ |
| 階層 | 半角空白2つで1階層 | 同じ |
| ラベル | `第５` `２` `⑴` `①` `ア` `・` など。番号は表示のまま持つ | 法令の条・項・号の代わりに、通知の番号体系を使う |
| 段落 | 全角空白で始まる行は、直前の項目の2段落目以降 | 通知では項目の中の「また、」「なお、」段落が多いため追加 |
| メタ情報 | 冒頭のYAMLに版と改正履歴を置く | 法令番号の代わり |
| 番号体系からの階層推定 | 第N → 数字 → ⑴ → ① → ア のように、番号の種類の並びで階層を決める | Lawtextの行解析と同じ発想。PDFの余白のずれに影響されない |

## 2. 新旧対照表テキスト（`*.shinkyu.txt`）＝ 改正そのもの

通知テキストの各行の先頭に**1文字の印**を付けたものです。`diff -u` に近い書き方で、新旧対照表の行の並びとも一対一に対応します。

```text
---
amendment: {kind: 一部改正, number: 老発0313第5号, date: '2026-03-13', effective: '2026-06-01'}
base_version: R7.3.13        ← この版にしか適用できない
new_version:  R8.3.13
forms: [{label: 別紙１―１, change: 内容変更有}, …]
---
 第１～第４　（略）
 第５　体制状況一覧表の記載要領について
   １　各サービス共通事項
     ①～⑥　（略）
-    ⑦　10⑨、13⑩、…については、令和７年８月１日から適用することとする。
   ２　訪問介護
     ①～⑪　（略）
-    ⑫　「介護職員等処遇改善加算」については、大臣基準告示第四号イに…
+    ⑫　「介護職員等処遇改善加算」については、大臣基準告示第４号イに…
   ４　訪問看護
     ①～⑬　（略）
+    ⑭　「介護職員等処遇改善加算」については、大臣基準告示第10号の２に…
   22　介護予防訪問看護
     ①～⑪　（略）
+    ⑫　「介護職員等処遇改善加算」については、訪問看護と同様であるため、４⑭を準用すること。
     ⑬←⑫　（略）
```

| 書き方 | 意味 | 対照表での表示 |
|---|---|---|
| ` 見出し` | 文脈。原本の見出しと一致するか確認する | 左右とも同じ見出し |
| ` ①～⑪　（略）` | 変わらない範囲。原本にこの番号がこの順で並んでいるか確認する | 「①～⑪　（略）」 |
| ` ⑬←⑫　（略）` | 繰下げ（現行の⑫が⑬になる） | 「⑬（略）｜⑫（略）」、番号に傍線 |
| `-` の直後に `+` | 改める | 左右に本文、語句単位の傍線 |
| `+` だけ | 新設 | 現行側は「（新設）」 |
| `-` だけ | 削る | 改正後側は「（削る）」 |

**表示されている親の子は、すべて行として書く**という原則にしています。この原則は実際の対照表の慣行と一致します（たとえば「10～13（略）」のように、変わらない部分も範囲で必ず書かれています）。書き漏れがあれば `apply` が検出します。

## 3. 操作

### 階層的な通知（介護・診療報酬）

```bash
python pdf2tsuchi.py  原本.pdf -o 原本.tsuchi.txt --number 老発0315第1号 --date 2024-03-15 --version R6.3.15   # 原本PDF → 通知テキスト（初回だけ）
python pdf2shinkyu.py 改正.pdf --pages 2-8 -o 改正.shinkyu.txt --number 老発0313第5号 --date 2026-03-13 \
                      --base-version R7.3.13 --new-version R8.3.13                                        # 既存の新旧対照表PDF → 改正テキスト（初回だけ）
python shinkyu.py apply  旧.tsuchi.txt 改正.shinkyu.txt -o 新.tsuchi.txt --patch-out 改正_完成版.shinkyu.txt   # 改正を反映（参照の追従つき）
python shinkyu.py apply  旧.tsuchi.txt 部分改正.shinkyu.txt -o 新.tsuchi.txt --partial   # 部分改正を反映（対照表に出てこないセクションは保持）
python shinkyu.py diff   旧.tsuchi.txt 新.tsuchi.txt -o 改正.shinkyu.txt                 # 全文を直接直した場合 → 改正テキスト
python shinkyu.py render 改正.shinkyu.txt -o 新旧対照表.html                             # 対照表を出力
python shinkyu.py lint   新.tsuchi.txt                                                  # 番号参照の点検
```

### 事務連絡（Administrative Circulars）

```bash
python pdf2jimu.py 事務連絡.pdf -o 事務連絡.jimu.txt   # 事務連絡PDF → 簡易テキスト（初回の取り込み用）
```

**対応範囲**: MHLW 事務連絡（介護保険最新情報 Vol.NNNN形式など）  
**取り込み内容**: 版メタデータ（種別・Vol・日付・発出課・件名）＋本文段落  
**対応範囲外**: 階層的な番号体系の強制、新旧対照表の適用、参照の追従

### 繰下げに合わせた番号参照の追従（apply に組み込み済み）

「２⑫を準用」「第五の34⑫」「③から⑩まで、⑫」のような参照を、繰下げ・繰上げ・途中の新設に合わせて自動で書き直します。

1. 改正前の版で、各参照が**どの項目を指しているか**を解決しておく（番号ではなく項目そのものを覚える）
2. 改正を反映した後、その項目の新しい番号で参照を書き直す。書式は元に合わせる（「第五」は漢数字のまま、「２」は全角のまま）
3. 書き直した項目は完成版の対照表テキスト（`--patch-out`）に `-`／`+` で入り、対照表では「２⑪」→「２⑫」に傍線が付く

```bash
python shinkyu.py apply R6.tsuchi.txt 中間改正.shinkyu.txt -o R7.tsuchi.txt --patch-out 中間改正_完成版.shinkyu.txt
#   参照を追従: /第５/14/⑳  ２⑪ → ２⑫
#   参照を追従: /第６/⑶/２/⑤  第五の２⑪ → 第五の２⑫   …
```

| 参照の書き方 | 解決のしかた |
|---|---|
| `２⑫` | サービスの一覧を持つ最も近い祖先（第５や第６⑶）から、サービス２の⑫を探す |
| `第五の34⑫` `第二の②` | 第N（漢数字・全角・半角）から探す |
| `②から⑥まで、⑨、⑩及び⑫` | 「から・まで・、・及び・又は」でつながっている間は、前の参照の「第」と「サービス」を引き継ぐ |
| 単独の `③` | 同じサービスの中の③ |

丸数字はこの通知の中の項目だけに使われています（告示などの外部参照は ⑴ ㈠ イ を使う）。そのため、丸数字を含む参照だけを対象にしています。R6原本では、453件の参照がすべて解決できました。

**止める・知らせる場合**

- 参照先が削られた → 知らせる（手で直す）
- 「②から⑥まで」の途中に新設がある → 端点は追従し、新設を範囲に含めるか確認を促す
- 改正で新しく書いた本文の参照先が存在しない → 誤りとして反映しない
- `lint`：「○○については、…を準用」で、参照先の項目名が違うものを挙げる。R6原本では2件見つかった（21③の「２⑥」は２⑧、51⑪の「40⑱」は40⑲の誤りと思われる）


### apply の検証内容（どれか1つでも通らなければ反映しない）

1. `base_version` が原本の版と一致すること
2. 見出し・（略）の番号・現行の文が、原本と一字一句一致すること（空白の違いは無視）
3. 表示されている親の子が、すべて対照表に出てくること（`--partial` 指定時はこの検証をスキップ）
4. 反映後の番号が連続していること（繰下げ漏れの検出）。原本にもともとある乱れは参考として表示する

### 部分改正モード（`--partial`）

実際の厚生労働省の保医発等のPDFでは、文書全体ではなく**特定のセクションだけ**の新旧対照表が公表されることがあります（例：「第２の６」だけを改正）。このような部分的な改正に対応するため、`--partial` フラグが用意されています。

```bash
python shinkyu.py apply 旧.tsuchi.txt 部分改正.shinkyu.txt -o 新.tsuchi.txt --partial
```

**通常モードとの違い：**

- 対照表に**出てこないセクション**は、原本のまま保持されます
- 「表示されている親の子がすべて対照表に出てくる」という検証が無効になります
- `base_version` の検証は**引き続き有効**です（異なる版への適用を防ぐため）
  - 版が違う場合は `--force` を併用してください

**参照の追従：**

部分改正モードでも、番号参照の自動追従は正常に動作します。例えば、対照表に出てこないセクションが改正されたセクションを参照している場合、その参照も自動的に更新されます。

**使用例：**

```bash
# 第２のサービス１だけを改正する部分的な新旧対照表を適用
python shinkyu.py apply R7.tsuchi.txt 部分改正_第２の１のみ.shinkyu.txt -o R8.tsuchi.txt --partial
```

### render の傍線

語句（漢字・カタカナ・数字のまとまり、ひらがなのまとまり、記号）の単位で比べ、変わった語句に傍線を引きます。ほとんど書き換わった項目（一致率50%未満）は全体に引きます。R8の対照表で人が引いた傍線と比べると、文字単位で**適合率95%、再現率83%**でした。差が出るのは、人が「加算Ⅰ～Ⅱロ」の塊をまとめて引いている箇所です。

## 5. 対応範囲と境界

### 現在の対応範囲（Priority A）

このツールは**階層的な番号体系を持つ通知の本体**（局長通知・留意事項など）を対象としています：

- **対応**：介護保険・診療報酬等の階層つき通知本体
  - 第N → 数字 → 丸括弧数字(⑴⑵⑶) → 丸数字(①②③) → イロハ → ・ の階層構造
  - サービス別の届出要領・留意事項（「第５　体制状況一覧表の記載要領について」のような構成）
  - 番号参照の自動追従（「２⑫を準用」「第五の34⑫」など）

### 対応範囲外（将来の拡張候補）

以下の文書種別は、現在のコアとは異なる構造を持つため、別のパーサーが必要です：

- **Q&A・疑義解釈**：問答形式、独自の番号体系（問N、QN など）
- **告示・省令本文**：法令形式（条・項・号）→ [Lawtext](https://github.com/yamachig/Lawtext) を参照
- **e-Gov API連携**、**国税庁HTML形式の通達**：別途アダプターが必要

### 事務連絡（Administrative Circulars）への対応（Priority A-lite）

**現状**: `pdf2jimu.py` により、MHLW 事務連絡（介護保険最新情報など）の**メタデータ取り込み＋本文段落抽出**に対応しました。

整備状況：
- ✅ J1–J3スタイル文書の取り込み（Vol・日付・発出課・件名・本文）
- ✅ テストカバレッジ（`tests/test_jimu.py`）

対応範囲：
- **対応**：版メタデータ（種別・Vol・日付・発出課・件名）の抽出、本文段落のプレーンテキスト化
- **対応範囲外**：階層的な番号体系の強制、新旧対照表の適用、`shinkyu apply`/`--partial`、参照の追従

事務連絡は通知（局長通知・留意事項）よりも軽い構造であり、階層的な番号体系を前提とした`pdf2tsuchi.py`の`accept`ロジックや`x-stack`とは異なるアプローチを取ります。

### 診療報酬通知（Priority A'）への対応準備

診療報酬改定の階層つき通知（告示の留意事項通知など）は、介護保険通知と同様の番号体系（第N → 数字 → ⑴ → ① → ア → ・）を使用しています。

**現状**: 合成フィクスチャでの検証により、既存のコアが診療報酬通知の番号パターンと参照追従機能を処理できることを確認しました。ただし、**実際のPDF（例：保医発0304第1号「基本診療料の施設基準等届出取扱い」）でのラウンドトリップテストが成功するまで、対応は暫定的（provisional）です**。

整備状況：

- ✅ 番号パターンのカバレッジテスト（`tests/aprime_coverage_test.py`）
